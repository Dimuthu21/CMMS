# CMMS UI-First Coding Rules (Copilot Instructions)

## Goal
Build **UI ONLY first** for a large CMMS system.
✅ Use **hardcoded JSON + localStorage store pattern** (NO DB now).
Later we will connect BAL/DAL/SP.

---

## 1) 3-Layer Architecture (Mandatory)

Projects:
- **CMMS_WEB** → UI only (Controllers + Views + JS)
- **CMMS_BAL** → Business logic only (later)
- **CMMS_DAL** → Models/Entities/Enums (later Dapper+SP)

Rules:
- Controllers must NOT contain business logic.
- BAL is the only layer that can call DAL (when DB stage starts).
- DAL uses Dapper only (NO EF) and Stored Procedures only (later).
- For UI stage, DAL still holds **ViewModels/Entities/Enums**.

---

## 2) Folder + Naming Structure (Mandatory)

### WEB (UI)
Controllers must be modular:
- `CMMS_WEB/Controllers/Core/...`
- `CMMS_WEB/Controllers/HR/...`
- `CMMS_WEB/Controllers/Inventory/...`
- `CMMS_WEB/Controllers/Asset/...`
- `CMMS_WEB/Controllers/Maintenance/...`
- `CMMS_WEB/Controllers/System/...`

Views must be modular:
- `CMMS_WEB/Views/Core/...`
- `CMMS_WEB/Views/HR/...`
- etc.

### JS / CSS (IMPORTANT)
We do NOT use `Scripts/commn`.  
We use: **Content/Common** ✅

Shared JS:
- `CMMS_WEB/Content/Common/csm-common.js` (SweetAlert helpers, DataTable init, trim-start, form helpers)
- `CMMS_WEB/Content/Common/csm-data.js` (hardcoded lookups + localStorage store utilities)
- `CMMS_WEB/Content/Common/csm-init.js` (global init if needed)

Module JS:
- `CMMS_WEB/Content/Common/Core/BusinessPartner/*.js`
- `CMMS_WEB/Content/Common/Core/Uom/*.js`
- etc.

CSS:
- Keep minimal page css in `CMMS_WEB/Content/css/<Module>/...`
- Always use version query string: `?v=1.0.0`

### DAL (Models/Enums)
- Enums: `CMMS_DAL/Common/Enum_*.cs` (module separated)
- Models: `CMMS_DAL/Modules/<Tile>/<Module>/Models/...`
- Entities: `CMMS_DAL/Modules/<Tile>/<Module>/Entities/...`

Naming rules:
- Use clear names: `BusinessPartnerCreate.cshtml`, `BusinessPartnerList.cshtml`
- JS: `businesspartner-create.js`, `businesspartner-list.js`
- No unclear short names.

---

## 3) UI Rules (Mandatory)

- Responsive UI using Bootstrap grid (NO fixed widths).
- Use **HTML Helpers**:
  - `@Html.TextBoxFor`
  - `@Html.HiddenFor`
  - `@Html.DropDownListFor`
  - `@Html.ValidationMessageFor` or per-field `<span class="text-danger">...`
- Validation messages must appear near fields (NOT only top summary).
- Use **SweetAlert2** for:
  - Save/Update success
  - Delete confirmation
- Use **DataTables** for list pages:
  - pagination
  - show entries (10/20/30…)
- Trim leading spaces:
  - inputs have class `trim-start`
  - common JS must enforce trim.
- Dropdown caret icon must show using wrapper:
  ```html
  <div class="position-relative">
    <select class="form-control"></select>
    <i class="fa fa-caret-down position-absolute" style="right: 12px; top: 50%; transform: translateY(-50%); pointer-events:none;"></i>
  </div>
4) Strict DO NOT Rules (Mandatory)
❌ Don’t use ViewBag for passing data (except ViewBag.Title only)
❌ Don’t put JS inside .cshtml (module JS files only)
❌ Don’t duplicate JS logic across pages (shared logic goes to Content/Common)
❌ No inline SQL
❌ No EF / LINQ-to-SQL
❌ No ugly spacing / fixed widths
❌ No magic strings when enums/lookups exist
❌ Never bypass trimming/validation

5) UI-Only Data Rules (Mandatory)
All data must use localStorage store pattern.

Reusable lookups must live ONLY in csm-data.js:

Status (Active/Inactive)

Currency (HKD, LKR, S$, USD, Yen)

Designation (CEO, Assistant Manager, HR Manager, IT Manager, etc.)

Credit Card Type (Master, Visa)

Business Partner Type (Supplier, Customer)

DO NOT redefine the same lookup in multiple files.

Master dropdowns must reuse saved masters:

Trustee dropdown must read from Trustee store

Sector dropdown must read from Sector store

Industry dropdown must read from Industry store

6) Behavior Rules (Mandatory)
Create/Edit Master Screens (Trustee/Sector/Industry/etc.)
Code auto generated by JS (ex: TE1001, SE1001, IND1001)

User Preferred toggle:

ON → code editable

OFF → code readonly and auto generated

Status default = Active

Save → SweetAlert success and persist to localStorage

Double click row → load into form for edit

Delete icon → SweetAlert confirmation → soft delete (isDeleted=true)

Buttons must be in a separate card panel (Clear/Save/Reset)

List Screens
Filters in their own card panel

DataTables pagination enabled

Double click row opens edit page with saved data

7) Tile Menu Rule (Core, HR, Inventory, Asset, Maintenance, System)
When user is inside a Tile:

Navigation must show only that Tile’s menu.
Example:

In Core tile → show Core menu only (Business Partner, UOM, etc.)

Other tile menus must be hidden.

8) Versioning (Mandatory)
Every CSS/JS include must use version:

...css?v=1.0.0

...js?v=1.0.0

Output Expectations for Copilot
When generating code:

Always provide complete code files (Controller + View + JS).

Always follow folder structure.

Always use localStorage + csm-data store pattern.

No DB, no API calls, no ViewBag data passing.
